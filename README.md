### 1. Задание 2.11 (2 уровень сложности)

**Формулировка задания:**
Напишите код, объединяющий любое количество плоских массивов цифр в один. Функция должна вернуть строку, в которой будут идти все полученные цифры в порядке убывания их значений через пробел.

**Реализация:**
В приложении на странице `dz1` реализовано слияние двух массивов, вводимых пользователем через пробел. 

```js
// pages/dz1/index.js
document.getElementById('merge-btn').addEventListener('click', () => {
    const firstRaw = document.getElementById('first-array').value.trim();
    const secondRaw = document.getElementById('second-array').value.trim();

    // Преобразуем введенные строки в числовые массивы
    const arr1 = firstRaw ? firstRaw.split(/\s+/).map(Number) : [];
    const arr2 = secondRaw ? secondRaw.split(/\s+/).map(Number) : [];
    
    // Объединяем массивы и сортируем по убыванию (b - a)
    const arr3 = [...arr1, ...arr2].sort((a, b) => b - a);

    // Выводим результат через пробел
    document.getElementById('result-array').value = arr3.join(' ');
});
```

**Пример работы:**
* Ввод 1: `1 2 3`
* Ввод 2: `-1 -10 20`
* Вывод: `20 3 2 1 -1 -10`

### 2. Задание 3.6 (3 уровень сложности)

**Формулировка задания:**
Напишите функцию `rle`, которая реализует RLE-сжатие (Run-Length Encoding).

**Реализация:**
RLE — это алгоритм сжатия данных, в котором повторяющиеся символы заменяются на символ и количество его повторений.

```js
// pages/dz1/index.js
function rle(str) {
    if (!str) return '';
    let result = '';
    let count = 1;
    
    for (let i = 1; i <= str.length; i++) {
        if (i < str.length && str[i] === str[i - 1]) {
            count++;
        } else {
            // Записываем число повторений и сам символ
            result += count > 1 ? count + str[i - 1] : 1 + str[i - 1];
            count = 1;
        }
    }
    return result;
}

document.getElementById('rle-btn').addEventListener('click', () => {
    const input = document.getElementById('rle-input').value;
    document.getElementById('rle-output').value = rle(input);
});
```

**Пример работы:**
* Ввод: `AAABBBCCDDDDEE`
* Вывод: `3A3B2C4D2E`

# Домашнее Задание 2 — 3D Gallery (GLB)

## 🚀 Как это работает

* **Главная страница (`index.html`):** Отображает сетку карточек (4 в ряд) с 3D-превью моделей. Реализован рендеринг в режиме "single frame" (один кадр), что минимизирует нагрузку на GPU при выводе множества канвасов на экран.
* **Локальное хранение (IndexedDB):** Пользователь может загрузить свои `.glb` файлы через форму в шапке. Файлы сохраняются в IndexedDB браузера (на клиенте) и не отправляются на сервер. Для них динамически создаются новые карточки в галерее.
* **Страница просмотра (`detail.html`):** По клику на карточку открывается страница детального просмотра модели, где подключены `OrbitControls` для вращения, масштабирования и перемещения камеры.
* **Вспомогательные ракурсы:** На странице деталей доступны кнопки быстрого переключения стандартных ракурсов камеры (Вид спереди / сзади / слева / справа).
* **Парные модели:** Реализована поддержка группировки и одновременного рендеринга двух моделей на одной карточке (например, «Машина + Дерево») с программным расчетом отступов.

## 💡 Технологии

* **Three.js** (импортируется через `importmap` с CDN `unpkg.com` или `jsDelivr`).
* **GLTFLoader** — загрузчик трехмерных объектов формата GLTF/GLB.
* **OrbitControls** — модуль интерактивного управления камерой с помощью мыши/тачпада.
* **IndexedDB** — встроенная в браузер СУБД для надежного хранения бинарных файлов моделей (Blob) на стороне клиента.
* **Vanilla HTML5 / CSS3** — вёрстка сетки карточек без использования тяжелых CSS-фреймворков.

## 🖱️ Функции интерфейса

1. **Список моделей:** Каждая карточка является отдельным 3D-вьювером с трехмерной моделью.
2. **Форма загрузки файлов:** Кнопка «Выбрать файл» в шапке позволяет выбрать локальный `.glb`, прочитать его через `FileReader` и записать в IndexedDB.
3. **Управление камерой на странице деталей:**
   - Свободное вращение левой кнопкой мыши.
   - Панорамирование (сдвиг) правой кнопкой мыши.
   - Приближение/отдаление (зум) колесиком или кнопками **«+»** и **«–»**.
   - Кнопки **«Спереди», «Сзади», «Слева», «Справа»** для мгновенной переустановки позиции камеры по соответствующим осям координат.
4. **Центрирование геометрии:** Модели автоматически масштабируются и позиционируются так, чтобы их нижний край (основание) соприкасался с виртуальным уровнем земли `Y = 0`.

## 📝 Вопросы на защите и важные аспекты реализации

### 1) Как устроено хранение и загрузка пользовательских 3D-моделей на клиенте без участия сервера?
**Ответ:** Для этого используется встроенная в браузер база данных **IndexedDB** (реализованная в `idb.js`). 
При загрузке файла через форму `<input type="file">` событие перехватывается, файл считывается как объект `Blob` с помощью `FileReader` и сохраняется в IndexedDB в виде пары ключ-значение (где ключ — сгенерированный ID или имя файла, а значение — бинарные данные модели). 
При инициализации галереи мы считываем файлы из IndexedDB, преобразуем их во временные ссылки с помощью `URL.createObjectURL(blob)` и передаем полученные URL в `GLTFLoader.load()` для визуализации.

### 2) Как реализована автонастройка камеры и центрирование разноразмерных моделей при их загрузке?
**Ответ:** Загружаемые 3D-модели могут иметь произвольные размеры и смещенные центры координат. Чтобы они отображались корректно, в `detail.js` после загрузки сцены вычисляются габариты объекта с помощью класса `THREE.Box3`:
```js
const box = new THREE.Box3().setFromObject(model);
const center = box.getCenter(new THREE.Vector3());
const size = box.getSize(new THREE.Vector3());

// Находим максимальный размер модели и масштабируем под единую сетку
const maxDim = Math.max(size.x, size.y, size.z);
const scale = 2 / maxDim; // Приводим к масштабу 2 единицы
model.scale.setScalar(scale);

// Сдвигаем модель так, чтобы центр bounding box совпал с (0, 0, 0)
// и опускаем основание модели на пол (Y = 0)
model.position.sub(center.multiplyScalar(scale));
model.position.y -= (box.min.y * scale); 
```
